## Implementation and acceptance

1. Continue current PR33 branch after checking actual checkout/CI. Preserve untracked generated files. Reuse actor bindings, WorkService and server-only PostgREST adapter.
2. GET /api/projects/:id/tasks accepts zero query parameters or exactly one cursor. Other parameters, duplicate cursor and POST queries reject400. Reauthenticate at the origin and resolve the current trusted project catalog on every page. Cursor is only a record-position selector, never authority. Owner/project revocation denies later pages. Bootstrap remains disconnected.
3. Cursor is bounded base64url JSON with exactly projectId, createdAt and id; reject malformed/noncanonical base64, wrong project, unknown fields, invalid UUID/date or oversized input. Keep UTC PostgreSQL microseconds: do not round to JavaScript milliseconds. Query fixed project_id plus (created_at less than boundary OR same creation time and lower UUID), ordered by created_at DESC,id DESC. Request51, validate every row including lookahead, return50 normalized task descriptors and nullable nextCursor. Reject duplicate/unordered/overlapping/malformed data, never false-empty. Existing internal list method remains unchanged.
4. UI replaces one page at a time, showing at most50 task cards. Older tasks appears only for a valid continuation. Refresh returns to newest; project changes reset paging. Preserve draft across page/refresh and cancel stale reads. Failed page reads retain unknown/unavailable state and block creation until recovery. A confirmed create from an older/full page reloads newest to avoid hiding a displaced boundary record. No automatic polling or fake totals.
