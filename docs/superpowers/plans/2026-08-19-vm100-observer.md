# FRIDAY VM100 Observer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a token-authenticated, read-only Docker observer on VM 100 and integrate it into the FRIDAY controller on VM 102 without exposing Docker's native API or adding infrastructure mutation capability.

**Architecture:** VM 100 runs a small Node.js observer that mounts `/var/run/docker.sock` read-only and exposes only `GET /health` and `GET /api/v1/containers` on management address `192.168.1.74:3199`. FRIDAY on VM 102 (`192.168.1.64`) calls that observer with a bearer token, maps sanitized container records into the existing overview, and treats observer failures as degraded integration alerts. Proxmox remains a separate read-only integration and VM 102's local Docker socket remains disabled by default.

**Tech Stack:** Node.js 22 built-ins, Docker Engine API over Unix socket, Docker Compose, existing FRIDAY Node server, `node:test`, Vitest, TypeScript/Vite, shell scripts.

**Spec:** `docs/superpowers/specs/2026-08-19-vm100-observer-design.md`

## Global Constraints

- VM 102 (`friday-controller`, `192.168.1.64`) is the authoritative FRIDAY controller.
- VM 100 is `192.168.1.74` and hosts the observer only; FRIDAY must not SSH into VM 100 for Docker control.
- Final observer port is `3199`; deployment MUST run `ss -ltn` on VM 100 first and abort if `192.168.1.74:3199` or `0.0.0.0:3199` is occupied. Do not silently choose another port.
- The observer exposes only `GET /health` and `GET /api/v1/containers`.
- No Docker native TCP API exposure.
- No create/start/stop/restart/kill/exec/remove/image/volume/network mutation code paths in the observer.
- Missing or invalid bearer tokens return HTTP `401`.
- Observer token stays server-side and must never use a `VITE_*` variable.
- VM 102 local Docker observation remains disabled by default.
- FRIDAY infrastructure mutation endpoints remain absent.
- Observer integration failures degrade the overview but never crash `/api/overview`.
- Secret-bearing `.env` files use mode `600`.
- All existing tests and production builds must remain passing.

- [ ] **Step 7: Implement GET-only Docker inventory and sanitization**

Implement `observer/docker.mjs` with Node's `http.request({ socketPath, path: '/containers/json?all=1', method: 'GET' })`. Core sanitization implementation:

```js
export function sanitizeContainer(container, { hostName, allowedLabelKeys, observedAt }) {
  const labels = Object.fromEntries(
    allowedLabelKeys
      .filter((key) => Object.hasOwn(container.Labels || {}, key))
      .map((key) => [key, container.Labels[key]])
  )
  return {
    id: String(container.Id || '').slice(0, 12),
    name: String(container.Names?.[0] || container.Id || 'unknown').replace(/^\//, ''),
    image: String(container.Image || ''),
    state: String(container.State || 'unknown'),
    status: String(container.Status || 'unknown'),
    ports: Array.isArray(container.Ports) ? container.Ports.map((port) => ({
      privatePort: port.PrivatePort,
      publicPort: port.PublicPort,
      type: port.Type,
      ip: port.IP,
    })) : [],
    labels,
    host: hostName,
    observedAt,
  }
}
```
